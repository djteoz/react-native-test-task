# Ревью: OptimizationList (Задание №2)

Компонент: `pages/review-list/review-list.tsx`

## Резюме

Компонент подходит для демо на 9 элементах, но **не готов к использованию со 100+ элементами**. Главные проблемы: `ScrollView` вместо виртуализированного списка, пересборка всего `data` при каждом символе в `TextInput`, нестабильные `key`.

**Вердикт:** требуется рефакторинг перед production-использованием. Критичность: высокая для perf, средняя для структуры проекта.

## Ответ на доп. вопрос

> Если элемент всегда первый или последний — можно оптимизировать?

**Да.** Если динамический элемент **гарантированно первый** — вынести его в `ListHeaderComponent` у `FlatList` (или `TextInput` + preview-строка там же). Если **гарантированно последний** — `ListFooterComponent`. Тогда изменение `value` не вызывает re-render остальных строк списка.

Дополнительно при фиксированной высоте строк: `getItemLayout`, `React.memo` для row-компонента, `useMemo` для статической части данных.
